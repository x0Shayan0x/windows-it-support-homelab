# NET-002 — Incorrect Static IPv4 Address

## Ticket Overview

| Field | Details |
|---|---|
| Ticket ID | `NET-002` |
| Category | Networking / IPv4 / DHCP |
| Type | Incident |
| Priority | Medium |
| Affected System | WIN1 — Ethernet (host-only adapter) |
| Status | Resolved |
| Tools Used | `ipconfig`, `ping`, `route print`, Windows IPv4 adapter settings |

## 1. Issue Description

A workstation was configured with an incorrect static IPv4 address on the host-only adapter.

Jira Ticket:

<img width="1843" height="427" alt="image" src="https://github.com/user-attachments/assets/41dd29b7-f7fa-4425-bdb9-0cead7cd2a5c" />


**Expected behavior:** The adapter receives an address on `192.168.56.0/24` through DHCP.

**Observed behavior:** The adapter was configured with `192.168.57.50/24`, outside the expected subnet. Importantly, the domain controller remained reachable by ping during the exercise.

## 2. Investigation and Troubleshooting

1. Reviewed `ipconfig /all` to inspect adapter addressing and DHCP status.

   <img width="715" height="787" alt="image" src="https://github.com/user-attachments/assets/c5ba9561-3421-4827-af8f-53ff56ab095e" />

2. Compared the misconfigured static address `192.168.57.50/24` against the expected host-only network `192.168.56.0/24`.
3. Tested connectivity to the domain controller at `192.168.56.10`.

   <img width="502" height="228" alt="image" src="https://github.com/user-attachments/assets/48835413-a657-4a8e-80a0-1aee7afd6b2a" />

4. Observed that the ping still succeeded, despite the incorrect static IP.

## 3. Root Cause / Request Context

The host-only Ethernet adapter had an incorrect manually assigned IPv4 address.

## 4. Resolution / Action Taken

1. Opened `ncpa.cpl` and selected the host-only Ethernet adapter.
2. Opened **Internet Protocol Version 4 (TCP/IPv4)** settings.
3. Restored automatic IP and DNS assignment.

   <img width="386" height="447" alt="image" src="https://github.com/user-attachments/assets/4760ef6b-fff2-44f8-93ec-3776eb2bccc3" />

4. Renewed the lease using `ipconfig /renew "Ethernet"` as part of the documented troubleshooting workflow.

   <img width="553" height="201" alt="image" src="https://github.com/user-attachments/assets/5358e770-1ea6-42d2-b373-57a5853c7ce0" />


## 5. Verification

- A previously observed working host-only configuration used `192.168.56.102/24`, DHCP server `192.168.56.100`, and DNS server `192.168.56.10`.
- The domain controller responded to ping even during the incorrect static IP configuration.
- Network resources were reachable ones these changes were made

## 7. Key Takeaways

A multihomed workstation can maintain connectivity through another adapter or route. Troubleshooting must distinguish an incorrect setting from a proven root cause of a reported outage.
