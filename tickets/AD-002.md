# AD-002 — Join Workstation to Active Directory Domain

## Ticket Overview

| Field | Details |
|---|---|
| Ticket ID | `AD-002` |
| Category | Active Directory / Workstation Management |
| Type | Service Request |
| Priority | Low |
| Affected System | WIN1 |
| Status | Resolved |
| Tools Used | System Properties (`sysdm.cpl`), Windows networking, Active Directory |

## 1. Issue Description

A workstation needed to be joined to the internal `lab.local` domain so it could use domain-based authentication and management.

Jira Ticket:

<img width="1821" height="160" alt="image" src="https://github.com/user-attachments/assets/f3183940-ae5c-48e2-81e8-c0fa6c7882ed" />


**Expected behavior:** WIN1 is a member of `lab.local` and can discover the domain controller.

**Observed behavior:** WIN1 is not currently a member of `lab.local` and cannot discover the domain controller.

## 2. Investigation and Troubleshooting

1. Checked the Windows client’s domain-join configuration using `sysdm.cpl`.
2. Used the internal DNS server address `192.168.56.10` for Active Directory name resolution.
3. Investigated domain-controller connectivity and secure-channel behavior during subsequent lab exercises.

## 3. Root Cause / Request Context

Not applicable as a fault diagnosis; this was a domain-join service request.

## 4. Resolution / Action Taken

1. Opened `sysdm.cpl` on WIN1.
2. Selected the option to join a domain and entered `lab.local`.
